# Инструкция по восстановлению бэкапа БД

## Восстановление бэкапа с другого ПК

Если у вас есть файл бэкапа в формате `tar.gz`, созданный на другом ПК, выполните следующие шаги:

### Шаг 1: Скопируйте файл бэкапа

Скопируйте файл бэкапа (например, `humorpedia_backup_20260119_121331.tar.gz`) в папку `backups/` в корне проекта:

```bash
# На хосте (не в Docker)
cp /путь/к/вашему/бэкапу.tar.gz ./backups/
```

### Шаг 2: Восстановите бэкап

#### Вариант A: Если БД пустая (рекомендуется для первого запуска)

Если база данных пустая, бэкап восстановится автоматически при следующем запуске контейнера:

```bash
docker-compose restart backend
```

Или просто перезапустите контейнеры:

```bash
docker-compose down
docker-compose up -d
```

#### Вариант B: Принудительное восстановление (перезаписать существующую БД)

⚠️ **ВНИМАНИЕ**: Это удалит все существующие данные в БД!

```bash
# В контейнере backend
docker exec -it humorpedia-backend python scripts/restore_specific_backup.py backups/имя_файла.tar.gz --force
```

Или если файл уже находится в папке `backups/`:

```bash
docker exec -it humorpedia-backend python scripts/restore_specific_backup.py имя_файла.tar.gz --force
```

#### Вариант C: Восстановление без перезаписи (если БД пустая)

Если БД пустая, можно восстановить без флага `--force`:

```bash
docker exec -it humorpedia-backend python scripts/restore_specific_backup.py имя_файла.tar.gz
```

### Шаг 3: Проверка результата

Проверьте логи восстановления:

```bash
docker logs humorpedia-backend | tail -50
```

Вы должны увидеть сообщение:
```
✅ Восстановление БД завершено успешно
```

## Примеры использования

### Пример 1: Восстановление последнего бэкапа

```bash
# Список доступных бэкапов
ls -lh backups/

# Восстановление конкретного файла
docker exec -it humorpedia-backend python scripts/restore_specific_backup.py humorpedia_backup_20260119_121331.tar.gz --force
```

### Пример 2: Восстановление с полным путем

```bash
docker exec -it humorpedia-backend python scripts/restore_specific_backup.py /app/backups/humorpedia_backup_20260119_121331.tar.gz --force
```

## Устранение проблем

### Ошибка: "Файл бэкапа не найден"

1. Убедитесь, что файл скопирован в папку `backups/`:
   ```bash
   ls -lh backups/
   ```

2. Проверьте, что файл имеет правильное имя и расширение `.tar.gz`

3. Убедитесь, что папка `backups/` смонтирована в контейнер (проверьте `docker-compose.yml`)

### Ошибка: "MongoDB не отвечает"

1. Убедитесь, что MongoDB запущена:
   ```bash
   docker ps | grep mongodb
   ```

2. Проверьте логи MongoDB:
   ```bash
   docker logs humorpedia-mongodb
   ```

### Ошибка: "Директория дампа не найдена"

Это может означать, что структура архива отличается от ожидаемой. Проверьте содержимое архива:

```bash
# На хосте
tar -tzf backups/имя_файла.tar.gz | head -20
```

Если структура отличается, возможно, нужно будет вручную распаковать архив и использовать `mongorestore` напрямую.

## Примечания

- Бэкапы создаются автоматически сервисом `backup` (см. `BACKUP_SYSTEM.md`)
- Восстановление с флагом `--force` **полностью удаляет** существующую БД перед восстановлением
- Рекомендуется сделать бэкап текущей БД перед восстановлением другого бэкапа
- Восстановление может занять некоторое время в зависимости от размера БД
