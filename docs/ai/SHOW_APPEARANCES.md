## Отображение

- Человек → команда → шоу: «Участник проекта «Звёзды на НТВ» в составе команды «Плюшки»».
- Человек → шоу, либо человек → дуэт/трио → шоу.
- Одна запись на человека и шоу. Сезоны не перечисляются.
- Подтверждённое высшее достижение: победитель, затем финалист, затем участник.
  Победа в выпуске не означает победы в шоу. В полуфинале участник ещё не финалист.
- Основной состав: ручное закрепление; иначе максимальное количество участий;
  при равенстве — первый подтверждённый выпуск. Если оба критерия неизвестны,
  выбор стабилен, но требует редакторской проверки. Популярность не вычисляется.
- Убойная лига: сводные таблицы участников и смешанных составов дают частоту;
  таблицы выпусков дают первое выступление. Сводка и выпуски не суммируются.
- На странице человека показывается отдельный блок участия в шоу. На странице шоу
  отдельный блок не создаётся: ссылки добавляются в уже существующие карточки участников,
  а таблицы выпусков и прочий контент остаются без изменений.
- Ссылки появляются только для опубликованных людей, шоу, страниц-источников и команд.
  Ожидающие и неоднозначные имена не превращаются в битые ссылки.

## Хранение и синхронизация

Коллекция `show_appearances` — варианты участия, связь по `person_id`, `show_id`,
необязательный `team_id`, имя/вид состава, достижение, частота, первый выпуск,
страница и раздел источника. Идентификатор детерминирован и не меняется от появления человека.
Исходные `shows`, `people`, `teams`, `memberships` синхронизация не переписывает.
Страница человека и проверенные ссылки в карточках шоу читают эту коллекцию, не дублируя
строки в биографиях и не переписывая исходные модули шоу.

Извлекаются карточки участников, явно обозначенные списки и колонки участников,
сезонные победители, финалы и составы команд. Ссылки в произвольных абзацах не
считаются участием. Старые страницы дуэтов в `people` раскрываются по первому
абзацу биографии; сами страницы сохраняются.

```bash
docker compose exec -T backend python scripts/sync_show_appearances.py
docker compose exec -T backend python scripts/sync_show_appearances.py --apply
```

Повторный запуск обновляет автоматические варианты, удаляет исчезнувшие из источника
автоматические записи и сохраняет ручные настройки для сохранившихся вариантов.
После правок шоу/составов нажать «Пересчитать связи» в админке. Кэш сбрасывается.
Если коллекция пуста (новая или восстановленная база), сервер автоматически выполняет
первичную синхронизацию после построения составов команд. Заполненная коллекция на старте
не пересчитывается, поэтому ручные решения не затрагиваются.

## Ручной выбор новых людей

Админка: `/admin/show-appearances`, кнопка «Участники шоу» в разделе «Шоу».
Доступ к списку и изменениям — editor/admin.

По умолчанию видны записи без страницы; доступны фильтры по шоу/имени, источник,
поиск существующего человека, исправление достижения и состава, исключение записи
и закрепление основного состава. Только кнопка на конкретной записи создаёт человека:
редактор проверяет имя и задаёт slug → создаётся черновик → открывается обычный
редактор человека. Массового создания или автоматической публикации нет.

После создания/сохранения человека ожидающие записи связываются по точному slug
или однозначному имени. До публикации публичные ссылки не появляются.
Удаление человека снимает связь, сохраняя исходное упоминание.

## API

- `GET /api/show-appearances/people/{person_id}` — упоминания на странице человека.
- `GET /api/show-appearances/review?q=&show_id=&unresolved=&skip=&limit=` — проверка.
- `POST /api/show-appearances/sync` — пересчёт из локального контента.
- `PATCH /api/show-appearances/review/{id}` — ручная связь/состав/достижение/исключение.
- `POST /api/show-appearances/review/{id}/create-person` — один выбранный черновик.

## Границы исходных данных

На момент разработки в 10 перенесённых командах Лиги Смеха нет записей составов,
а страница Outside Stand Up не содержит списка участников. Пустой результат
означает отсутствие извлекаемого подтверждения, а не отсутствие участников.
Неструктурированные или неоднозначные упоминания требуют редакторской проверки;
число автоматически найденных связей не является гарантией полноты истории шоу.
