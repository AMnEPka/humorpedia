# Импорт внешних материалов в редакционную очередь

21.10.2026. Разработка в `codex/local-page-builder`, первая версия 24СМИ начата от `50c397b`. Доставка четырёх источников выделяется в `codex/editorial-sources` от `origin/main`: коммиты конструктора страниц и рефакторинга в неё не включаются.

## Согласованный результат

Новости сайтов отбираются по существующим людям и шоу Юморпедии; биографии — по ссылкам редактора. В очередь поступает полный очищенный текст без фотографий, с источником. Редактор изменяет текст и связи, затем утверждает публикацию или отклоняет материал. Кнопка ручного запуска и ежедневный сбор новостей. После первой версии 24СМИ по запросу пользователя подключены Вокруг ТВ, GoStandup и новые посты публичного канала «ЖАБА — медиа-болото» по тому же редакционному процессу.

## Решения

- В существующем разделе «Редакционные находки» появится вкладка импорта. Полные материалы хранятся в отдельной закрытой коллекции `editorial_imports`: старая очередь проверенных отдельных фактов сохраняет свой контракт.
- До утверждения `people` и `news` не изменяются. Статус `draft` не используется для сокрытия: в проекте он публичный.
- Поля, совпадения личности, связи и источник видны при проверке. Для новой персоны сохраняется существующий минимум качества: имя, дата/место рождения, содержательная биография и два подтверждённых проекта. Для существующей персоны проверяется неизменность исходной версии перед заменой биографии.
- Упоминание шоу в биографии не означает участие самого героя. Новые связи биографии выбирает редактор; имеющиеся связи сохраняются. Новости автоматически получают найденные связи, которые можно исправить перед публикацией.
- Идентичность источника и хеш содержимого предотвращают повторные карточки; повтор утверждения не создаёт второй объект. Блокировки в Mongo защищают от одновременных запусков и решений.
- Сеть: только HTTPS и разрешённые URL четырёх источников, robots каждого домена, ограничения размера/времени и последовательные запросы. Переход редиректом к другому источнику запрещён. Импорт не выполняет внешний HTML/JS и не загружает медиа. HTTP 404 для robots означает отсутствие файла; 403/429/5xx не обходятся.
- Расписание хранится в БД, запускается backend, работает при запущенном стенде. Локально включается после проверки; время по умолчанию 10:00 Москвы. Первый обход — последние три дня, ограниченный пакет с видимым отчётом.

## Расширение 21.10: Вокруг ТВ и GoStandup

Согласован существующий процесс; отдельной публикации или автоматического рерайта не добавляли. Адаптеры и их тесты выполнялись двумя помощниками Luna/high, общая интеграция HTTP/очереди/расписаний/UI и финальные проверки — основной моделью.

| source_id | Биографии / тексты | Открытая лента |
|---|---|---|
| `24smi` | `https://24smi.org/celebrity/{id-slug}.html`, `/news/{id-slug}.html` | `/sitemap-news.xml` |
| `vokrugtv` | `https://www.vokrug.tv/person/show/{slug}/`, `/article/show/{id}/` | `/article/`, 20 последних карточек; query/pagination не используются |
| `gostandup` | `https://gostandup.ru/comedians/{slug}`, `/articles/{slug}` | `/articles`, только опубликованный HTML; запрещённый robots `/api` не используется |
| `zhaba` | Текстовые посты и подписи `https://t.me/zhabqua/{id}` | `https://t.me/s/zhabqua`, переходы только по опубликованным `rel=prev` |

`services/source_registry.py` — общий реестр источников: host/path allowlist, название для атрибуции, discovery URL и чистый адаптер. Новые параметры `source_id` добавлены совместимо: без него запросы расписания и запуска используют 24СМИ, а общий список очереди возвращает все источники. Сохранённые карточки 24СМИ и его включённое расписание не мигрируются.

В админке четыре кнопки источника переключают его очередь, отдельное расписание и отчёт. У карточки виден источник; `/import` сам определяет его по URL. Смена источника скрывает предыдущие карточки, запоздалый ответ другой вкладки не перезаписывает список. Все материалы сохраняются и утверждаются прежним редакционным механизмом; подпись источника выбирается по реальному домену URL.

Live smoke Вокруг ТВ: профиль Виктора Комарова и статья `/article/show/16116404521/` вернули 200, извлечены биография/данные рождения и датированный текст новости; discovery вернул 20 свежих ссылок. Live smoke GoStandup: профиль Кости Пушкина и статья о Богдане Лисевском вернули 200; дата/место рождения взяты только из `comic-page-birthdate__info-date` / `info-place`, текст — из подтверждённых контейнеров, без fallback на всю страницу. Свежих материалов GoStandup за 3–5 дней в текущем индексе нет; за 30 дней найден один.

GoStandup публикует календарную дату статьи без времени. При отборе она сравнивается по московскому календарному дню; время публикации не придумывается. Наивный datetime с часами без часового пояса по-прежнему считается ошибкой источника.

При живой проверке обнаружен отдельный дефект локального dev-runtime: Uvicorn `StatReload` упал с `OSError: [Errno 12] Cannot allocate memory` при обходе `/app/backups/images/...`, а дочерний сервер остался со старым кодом. Поэтому выполнен один восстановительный `docker compose restart backend`; после него OpenAPI содержит `source_id` и API проверен через реальный сайт. Следующая правка `source_import_scheduler.py` уже штатно подхватилась StatReload (в логах reload + startup complete). Обычное редактирование по-прежнему предполагает reload; сканирование тяжёлых backup/media каталогов наблюдателем требует отдельного исправления инфраструктуры.

**Результат расширения (21.10, текущий HEAD `405f05f`, изменения импорта незакоммичены):** в браузере проверены оба источника, реальный импорт, редактор, отдельные настройки и смешанный пакет URL. Добавлены 3 pending-материала: биографии Виктора Комарова и Кости Пушкина и свежая новость Вокруг ТВ о Надежде Сысоевой. Вокруг ТВ: просмотрено 20, создана 1 новость, 19 исключено, ошибок 0. GoStandup: за 3 дня свежих ссылок нет, ошибок 0. Повтор обеих биографий одним пакетом вернул два дубля, всего осталось 5 карточек (2 старых 24СМИ, 2 Вокруг ТВ, 1 GoStandup). Публичных записей новых источников 0. Ежедневный сбор всех трёх источников включён, следующий запуск 22.10.2026 в 10:00 МСК.

Итоговые проверки расширения: backend **919 passed, 9 skipped** (`SOURCE_IMPORT_INTEGRATION=1 pytest -q tests`), frontend **248 passed / 44 suites**, `yarn build` успешен (прежние warnings в других компонентах / Browserslist), `git diff --check` чист. `dev-status.ps1`: mounts и зависимости соответствуют checkout, backend/frontend отвечают, Mongo healthy. Независимое review проверило интеграцию источников; явное скрытие прежних карточек при переключении добавлено, обработка запоздалых ответов и сохранение черновика при polling покрыты тестами.

## Расширение 21.10: «ЖАБА — медиа-болото»

Ветка `codex/local-page-builder`, HEAD при проверке `a6a5d5e`; импорт остаётся локальным и незакоммиченным. Точный канал подтверждён: [@zhabqua](https://t.me/s/zhabqua). Открытая лента и конкретный пост доступны без авторизации; `robots.txt` возвращает обычный 404. Для HTTP используется публичный путь `/s/zhabqua/{id}`, а идентичность и ссылка источника — `/zhabqua/{id}`. Другие каналы, закрытые ссылки и Telegram API не подключены.

- Сбор берёт все новые текстовые посты и подписи к медиа, включая посты без совпадений в каталоге. Тип материала — `news`; найденные связи можно исправить перед утверждением. Фото, видео, просмотры и реакции не импортируются; посты без текста учитываются отдельно в отчёте.
- Первый запуск берёт последние три дня. После первого завершённого диапазона сохраняется `last_post_id`; последующие запуски догоняют все новые доступные посты после него, даже после простоя дольше трёх дней.
- Пагинация следует только `rel=prev` самой ленты. Перед обработкой страницы сохраняются её канонический snapshot, максимальный ID и исходная граница даты. Лимит 100 постов по кнопке (API до 200), 10 страниц или 10 минут оставляет checkpoint для следующего запуска. Ошибка не сдвигает итоговую позицию; уже обработанные посты при повторе пропускаются. Lease защищает от одновременных сборщиков.
- Автоматический сбор отслеживает новые ID. Изменение ранее обработанного поста можно явно загрузить по URL: новый хеш создаст отдельный материал для проверки и не заменит редакторский текст автоматически.
- Чистый парсер/тесты и Telegram UI выполняли помощники Luna/high; HTTP, продолжение сбора, Mongo/API, интеграция и проверки — основной агент. Независимое review проверило cursor/resume, лимиты, allowlist и robots; замечание об изменённых старых постах сверено с согласованным объёмом «новые посты» и описано выше.

**Живая проверка:** первый сбор просмотрел 21 пост на 3 страницах, создал 8 `pending`, пропустил 10 старых и 3 без текста, ошибок 0. Повтор: просмотрено 0, создано 0, ошибок 0; позиция `21963`, незавершённого checkpoint нет. Импорт `https://t.me/zhabqua/21963` через админку вернул «дубликат». Сохранение первой карточки увеличило `revision` до 2; все 8 по-прежнему ожидают решения. По ID импорта и slug публичных записей 0. Старые новости сайта могут уже ссылаться на этот Telegram-канал, поэтому подсчёт по любому упоминанию URL для этой проверки неприменим.

Ежедневный сбор ЖАБЫ включён в локальной БД: следующий запуск 22.10.2026 в 10:00 МСК. На новой БД источник по умолчанию выключен. Реальные посты не утверждались; редактирование и approve проверены в изолированной интеграционной БД. В браузере проверены вкладка, текстовый редактор/сохранение, отчёт, повторы и настройки.

Проверки: целевой набор источников **83 passed**; полный backend **953 passed, 14 skipped**, frontend **258 passed / 46 suites**, `yarn build` успешен (предупреждение о возрасте Browserslist). `git diff --check` без ошибок содержимого; Git предупреждает о LF/CRLF в параллельно изменённых файлах другой задачи. `dev-status.ps1`: mount текущего checkout, зависимости соответствуют sync, frontend/backend доступны, Mongo healthy.
