## Цель и границы

Отдельный тестовый стек MongoDB/backend/nginx. Первоначально доступ только через SSH-туннель; затем пользователь явно выбрал публичный HTTPS без дополнительного общего пароля. Текущий адрес https://77.105.139.231/. Старый сайт, DNS и почта не изменены. Пользователь разрешил отдельную сборку и чтение данных, затем краткую остановку локальных frontend/backend для согласованного экспорта. Они запущены обратно с прежними IDs; в операции экспорта MongoDB не останавливалась, локальная БД не изменялась. Ограничение о позднем общем перезапуске ниже. Во время этапа HTTPS локальный Docker не изменялся.

## Публичный HTTPS: выполнено и проверено

- Пользователь восстановил временный sudo и выбрал доступ без дополнительного общего пароля. Настроены host nginx 1.28.3 и Certbot 5.8.0 в отдельном venv из официального PyPI. Существовавшего host nginx/listeners 80/443 до настройки не было; созданные default-config и предыдущие конфиги сохранены. Приложение не обслуживалось на HTTP до доверенного сертификата.
- Успешны отдельный staging выпуск и production Let's Encrypt `humorpedia-vps-ip` с IPv4 SAN `77.105.139.231`, issuer YE1, профиль `shortlived`/webroot. Начальная валидность: 04.10.2026 06:01:55 UTC — 10.10.2026 22:01:54 UTC, около 160 часов. Staging не подключён к публичному nginx.
- TLS 1.2/1.3, host nginx IPv4 443 → Docker `127.0.0.1:8080`; HTTP 80 → 308 HTTPS, кроме ACME. Глобального IPv6 у VPS не обнаружено; TLS IPv6 listener не включён. UFW разрешает 22/80/443, backend/Mongo без опубликованных портов. Host nginx перезаписывает forwarding headers; Docker nginx доверяет только фактическому gateway 172.18.0.1, backend proxy trust ограничен неопубликованной сетью Compose. HTTPS-origin добавлен в CORS.
- Проверка Windows `curl.exe` без `--insecure`: HTTPS health 200/healthy и HTTP 308 на фиксированный IP. Runtime-smoke через реальный HTTPS: admin login/me, отказ неверного пароля и анонимной записи, CORS, каталоги, страница человека/медиа, wiki CRUD и upload/read/delete; exit0, собственные тестовые объекты очищены.
- Login ограничен 5 запросами/минуту на IP с burst 5, API — 10 запросов/секунду с burst 40. Восемь внешних пустых login POST дали 6×422, затем 2×429: проверен механизм throttling, не перебор паролей. Robots/noindex не являются защитой доступа. Дополнительных тестовых пользователей/ролей не создавали.
- Браузер по внешнему HTTPS без предупреждений: каталог людей с фото и форма admin/login. Ввод пароля и полный UI-login не выполнялись; успешный вход подтверждён API. Это не полный UI/security аудит.
- `certbot renew --dry-run --run-deploy-hooks` exit0: все simulated renewals succeeded, hook проверил nginx и перезагрузил его. Первая попытка отдельного systemd start одновременно с dry-run получила ожидаемую блокировку Certbot; после завершения dry-run повторный service start Result=success/ExecMainStatus=0. Никаких сертификатов/lock вручную не удаляли.
- Timer enabled, проверки дважды в сутки плюс jitter до часа; дополнительная случайная задержка Certbot отключена в service. Nginx enabled. Certbot без email; мониторинг ошибок/оповещения отдельно не настроены. Реальная будущая автоматическая выдача ещё не наступила; механизм проверен dry-run.
- Итоговый `verify-final.js`: 29 коллекций/34 254 документа, counts совпали, least-privilege Mongo-app и allocator fallback сохранены. Все 3 контейнера healthy, restart0/OOMfalse; Mongo/frontend при настройке HTTPS не пересоздавались, backend пересоздан для proxy/CORS env. Свободно 1,4 ГБ, available RAM 626 МБ, swap used 277 МБ; это снимок после проверок, не нагрузочная характеристика.
- HTTPS state (Let’s Encrypt account/cert/private key, nginx и timer) сохранён mode600 только на VPS; SHA256 `c8adedc6111e68012b08e5e4d85edf35db52156d0bffcb7a8931ff00f902da86`. Первоначальный перенос отклонён auto-review; обход не выполнялся. Пользователь затем явно выбрал «Не скачивать, оставить на VPS». Это не блокирует HTTPS. Временный NOPASSWD после настройки снова отключён; исходное правило сохранено в root backup.
- Источники: [официальный выпуск IP-сертификатов через Certbot](https://letsencrypt.org/2026/03/11/shorter-certs-certbot), [shortlived/IP GA](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability), [Certbot 5.8.0](https://pypi.org/project/certbot/5.8.0/).

## Проверка готовности

Новые SSH-подключения после hardening; публичные порты только SSH/HTTP redirect/HTTPS; доверенный HTTPS, сайт, API admin-вход, медиа и тестовая запись; пробное продление с reload; восстановление копии БД без ошибок; сохранение данных и автозапуск контейнеров после reboot первоначального этапа; внешняя копия; отсутствие OOM/циклических restart. После добавления HTTPS отдельный reboot не выполнялся, enabled nginx/timer проверены. Локальные контейнеры не пересозданы.
