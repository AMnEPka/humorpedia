## Повторный запуск

Из корня проекта:

```powershell
docker compose cp .\content\show-seasons-2026.json backend:/tmp/show-seasons-2026.json
docker compose exec -T backend python scripts/import_show_seasons_2026.py /tmp/show-seasons-2026.json
docker compose exec -T backend python scripts/import_show_seasons_2026.py /tmp/show-seasons-2026.json --apply --backup-dir /app/backups/show-seasons-2026
```

По умолчанию dry-run. Перед записью проверяются обе страницы, итоги и полнота колонок.
Фиксированные ID новых модулей делают повторный импорт пустой операцией.
Изменённый редактором сезон или существующий сезон с другими ID блокирует автоматическую перезапись.
Запись проверяет прежние `modules` и `updated_at`, чтобы не потерять параллельную правку.
После записи сбрасывается кэш во всех воркерах.

Резервные копии перед применением лежат в игнорируемом Git каталоге `backend/backups/show-seasons-2026/`:

- `standup-20261001T093009141370Z.json`
- `standupwomen-20261001T093009128261Z.json`

Запись двух страниц не является общей транзакцией. При конфликте после первой записи её резервная копия остаётся, кэш сбрасывается, повторный dry-run показывает состояние обеих страниц.
