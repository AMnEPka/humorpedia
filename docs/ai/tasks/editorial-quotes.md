## Инструмент и сохранённые данные

Скрипт: [normalize_editorial_quotes.py](../../../backend/scripts/normalize_editorial_quotes.py).
По умолчанию формирует отчёт; для применения нужен отдельный `--apply` с путём
к плану. Адресные ручные восстановления ограничены документом и полем.
HTML разбирается с сохранением исходных смещений: теги и атрибуты не пересоздаются.
Пары могут проходить через inline-теги и `<br>`, но не связывают разные ячейки
или абзацы. Повреждённые фрагменты и конфликты названий попадают в отчёт.

До первой записи проверяются исходные значения всего плана, а каждая запись
повторяет сравнение изменяемых полей. Используется `$set` только изменённых
корневых полей и `updated_at`; исходные значения сохраняются до записи.
После применения обновлено поколение кэша через `invalidate_everywhere`.

Локальные артефакты в игнорируемом Git каталоге `backups/editorial-quotes-2026-10-03/`:

- `before.json` — снимок исходных редакционных и связанных коллекций;
- `final/plan.json`, `changes.json`, `applied.jsonl` — значения до/после и журнал;
- `final/summary.json`, `integrity.json`, `live-verification.json` — проверки;
- `after/summary.json` — повторный проход: 0 изменений, 0 спорных случаев.

Снимок не следует импортировать целиком поверх живой базы. Для адресного
восстановления брать только поля нужного документа из `final/plan.json`, сверяя
текущее значение с сохранённым `after`, чтобы сохранить более поздние правки.
