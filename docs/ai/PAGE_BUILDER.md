# Локальный конструктор и перенос страниц

Конструктор `/admin/page-builder` готовит человека, команду КВН или корневое шоу из материалов редактора. Данные результата — обычные `PersonCreate` / `TeamCreate` / `ShowCreate`, штатные факты, изображения, SEO, теги и модули. После импорта страницу полностью редактируют через стандартные формы `/admin/people/:id`, `/admin/teams/:id`, `/admin/shows/:id`.

## Использование

1. Запустить обычный локальный Docker-стенд через `scripts/dev-sync.ps1`.
2. Проверить вход в Codex CLI: `codex login status`; при необходимости выполнить `codex login` самостоятельно.
3. Запустить `powershell -ExecutionPolicy Bypass -File .\scripts\start-page-builder.ps1`. Исполнитель работает отдельным скрытым процессом Windows. Остановка — та же команда с `-Stop`.
4. В админке открыть «Конструктор страниц», выбрать тип, заполнить материалы и загрузить изображение. Изменения сохраняются автоматически; при ошибке сохранения сообщение остаётся на экране.
5. Нажать «Собрать страницу». Codex формулирует текст по предоставленным фактам. Он не ищет недостающие сведения в интернете. Неизвестные данные остаются предупреждениями/вопросами, а не запретом на создание.
6. Сравнить предложение с текущей страницей, явно принять и при необходимости отредактировать. Генерация сама по себе не заменяет ручные правки. Устаревшее предложение после изменения исходной ревизии принять нельзя.
7. Проверить предпросмотр, отметить ручную проверку и скачать `.humorpedia.zip`.
8. В админке целевого сайта открыть «Импорт страницы», загрузить ZIP, проверить конфликты и связи. Отсутствующие связанные страницы нужно создать заранее или явно исключить связи. Нажать создание страницы и перейти к обычному редактору.

Codex CLI использует существующий вход ChatGPT и сетевую модель; это не офлайн-генерация. Отдельный API-ключ приложению не нужен. Учетные данные не копируются в Docker и не входят в ZIP.

Worker нужно запускать из обычного PowerShell пользователя, с доступом к сети. Если его запустил агент внутри ограниченного sandbox, процесс может унаследовать запрет сокетов Windows (`10013`) и ждать до таймаута. В таком случае остановить только этот worker через `-Stop` и запустить указанной командой из обычного терминала; при запуске агентом использовать штатное разрешение выполнения вне sandbox. Это не требует запуска Windows от имени администратора.

## Границы первой версии

- Только новые страницы. Повтор того же пакета не создаёт копию и не перезаписывает ручную редактуру. Другой пакет той же заготовки после импорта требует работы через обычный редактор.
- Команды — КВН; шоу — корневые. Перенос дерева сезонов/игр, дочерних шоу и команд шоу не входит в этот формат.
- Поддерживаются текст, факты, основные изображения, галереи, таблицы, цитаты, хронология и карточки участников шоу; импортируемые модули ограничены проверяемым списком `services/page_packages.py`.
- Связи между разными базами сопоставляются по типу и slug/пути. Mongo ID исходной базы не переносятся.
- Дата рождения может быть неполной. Недостающие дата, город, фото или известные шоу не блокируют редакторское решение.
- Проверка происхождения текста помогает сопоставлению с фактами, но не доказывает достоверность формулировок: финальную проверку делает редактор.

## Устройство

- `page_builder_drafts`: отдельные закрытые заготовки; CAS по `revision`, версии предложений и состояние текущего задания. В публичных коллекциях до импорта документов нет.
- Backend пишет immutable snapshot задания в `PAGE_BUILDER_DIR/jobs/<uuid>/input.json` и читает результат. Worker вызывает установленный CLI в режиме `exec`, read-only sandbox, ephemeral, JSON Schema, без загрузки пользовательской конфигурации инструментов. Это ограничение действий CLI, не отдельная виртуальная машина.
- `scripts/page-builder/worker.py`: очередь, heartbeat, таймаут, отмена с дочерними процессами, проверка JSON и fact IDs. После аварийного перезапуска требуется явный повтор; неограниченного автоматического повтора генерации нет.
- `page_package_imports`: закрытая проверка пакета и журнал применения. `page_package_entities`: уникальное резервирование исходной сущности через `_id`.
- ZIP v1: `manifest.json`, `page.json`, `relations.json`, `editorial.json`, изображения `assets/*`. Manifest содержит версии, идентичность заготовки и SHA-256/размер каждого файла. Изображения внутри page обозначены `asset:<id>`.
- На импорте ZIP проверяется повторно, создаётся обычная архивная страница, затем связи; успешное завершение атомарно помечает её опубликованной. Восстановление после этого момента только завершает журнал, не меняет страницу и связи. Ручное изменение незавершённой страницы останавливает повторное применение.
- Импортированные файлы находятся в `PAGE_PACKAGE_DIR/published`, вне общего StaticFiles; `/uploads/page-packages/...` выдаётся отдельным маршрутом только после публикации. Это закрывает обход через нормализацию URL. Изображения регистрируются в обычной медиатеке.
- Архивные люди/команды/шоу доступны редактору, но закрыты для публичных прямых чтений, списков и связанных составов.

## Настройки и развёртывание

`LOCAL_PAGE_BUILDER_ENABLED=true` разрешён только при `ENVIRONMENT != production`. В локальном Compose задан явно; маршруты конструктора в production не регистрируются. Импорт доступен редактору на любом окружении. Worker не получает секреты БД/приложения из окружения.

Локальные private bind mounts: `var/page-builder` и `var/page-packages`; оба исключены из Git. В cloud Compose для пакетов предусмотрен volume `page_packages_data:/app/private/page-packages`.

В любом другом deployment-манифесте необходимо задать постоянный закрытый `PAGE_PACKAGE_DIR` и направлять `/uploads/page-packages/*` в backend, а не в nginx static alias. Резервировать нужно MongoDB **и** этот каталог, включая `published/`: там находятся импортированные изображения. Текущий VPS использует отдельный `scripts/vps-test/compose.yml`; этот конструктор сам его не развёртывает и не обновляет.

API: `/api/page-builder/drafts` (CRUD заготовок, assets, generate, cancel, accept, export), `/api/page-packages/capabilities`, `/preview`, `/{id}`, `/{id}/assets/{asset_id}`, `/{id}/apply`. Закрытые маршруты используют `require_editor`. Приватные ответы/изображения не кэшируются публично.

Проверки: `pytest tests/test_page_builder.py tests/test_page_packages.py`; интеграция отдельной временной MongoDB — `PAGE_PACKAGE_INTEGRATION=1 pytest tests/test_page_package_import.py`; worker — `python -m unittest discover -s scripts/page-builder -p test_worker.py`; frontend — обычный Jest suite и `yarn build`.

Статус конкретной реализации и проверок: [local-page-builder-status.md](tasks/local-page-builder-status.md).
