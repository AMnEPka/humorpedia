# Правила работы с Humorpedia

Основной проектный контекст и карта документации находятся в [CLAUDE.md](CLAUDE.md). Общение с пользователем — на русском.

## Local-first Docker

- В основной папке один раз установить hooks: `powershell -ExecutionPolicy Bypass -File .\scripts\dev-hooks.ps1`. Локальные `post-checkout` и `post-merge` автоматически вызывают `dev-sync.ps1 -Auto`; дополнительные worktree игнорируются. Hooks хранятся в `.git`, поэтому работают и на старых ветках. При изменении самих hooks повторить установку.
- После создания, переключения или обновления ветки основной агент до редактирования проверяет успешный sync. Если hooks не установлены или завершились ошибкой, запустить из корня `powershell -ExecutionPolicy Bypass -File .\scripts\dev-sync.ps1`. Ошибка hook не отменяет уже выполненный checkout/merge: проверить фактическую ветку и устранить причину.
- После merge PR через Codex обязательно выполнить `powershell -ExecutionPolicy Bypass -File .\scripts\dev-finish.ps1 -PullRequest <номер>`: fetch origin, проверка MERGED/base main/точного HEAD и наличия merge в origin/main, проверка чистоты папки, переход на main, fast-forward, sync и проверка сайта. Поддерживаются merge/squash/rebase. Для локального Git merge без PR параметр не нужен: HEAD должен быть предком origin/main. Удалённый merge сам по себе не запускает локальный hook. Не завершать задачу после одного `gh pr merge`.
- Незакоммиченные изменения, незавершённые Git-операции и расхождение main останавливают возврат; автоматические stash/reset/clean запрещены. Команда `scripts/dev-status.ps1` показывает текущую папку/ветку/HEAD, последнюю синхронизацию, соответствие зависимостей, mount и доступность сайта.
- Обычные изменения в `backend/**/*.py` и `frontend/src/**/*` должны подхватываться автоматически. Backend работает с Uvicorn reload, frontend — с polling и hot reload. Ручной restart не является штатным способом разработки.
- После изменения `requirements*.txt`, `package.json`, `yarn.lock`, Dockerfile или Compose нужно повторно выполнить полный `dev-sync.ps1`. В режиме `-Auto` сборка и установка пакетов пропускаются только при совпадении сохранённых хешей и образов; ручные `-SkipBuild`/`-SkipFrontendDependencies` отклоняются, если соответствующие файлы изменились или нет успешной синхронизации.
- Тесты и `yarn build` не доказывают, что запущенный сайт обновился. Перед commit и особенно перед push проверь релевантный путь через `http://localhost:3000` и/или `http://localhost:8001`, а также `docker compose ps`.
- База `mongo_data` общая между ветками и не сбрасывается автоматически. Не выполнять миграции или разрушительные операции при переключении ветки без отдельной необходимости и проверки.
- Автоматический sync останавливается до изменений Docker, если ветка требует другой образ MongoDB, чем существующий контейнер. Старые ветки не должны автоматически понижать версию общей базы; обновление БД требует отдельной проверки.
- В дополнительных worktree не поднимать второй стек с теми же `container_name` и портами. Локальным стеком управляет основной агент активного checkout; субагенты Docker не перезапускают.
